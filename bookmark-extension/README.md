# Resource Hub 书签桥（浏览器扩展）

一个 **Chrome / Edge 通用** 的 Manifest V3 扩展：让 Resource Hub 与本机浏览器书签保持同步
（支持 **删除书签** 与 **重命名书签**），只与本机 `127.0.0.1` 上的 Resource Hub 程序通信，
不联网、不上传任何数据。

> 说明：扩展文件夹 `bookmark-extension/` 会随发布包一起放到 `resource_hub.exe` 同级目录。
> 加载时选择**本文件夹**即可，不要单独复制里面的文件。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | 扩展清单（权限、service worker 声明） |
| `background.js` | 后台 service worker：端口发现、命令轮询、书签事件上报 |
| `README.md` | 本说明 |
| `check_protocol.py` | 协议自检脚本（CI 用，不需要浏览器） |

## 30 秒安装（Chrome）

1. 先启动 **Resource Hub** 程序（`resource_hub.exe` 或启动脚本），让本机桥接服务运行起来。
2. 浏览器地址栏输入 `chrome://extensions` 并回车。
3. 打开右上角的 **开发者模式**（Developer mode）。
4. 点击左上角 **加载已解压的扩展程序**（Load unpacked）。
5. 选择本文件夹 `bookmark-extension`（与 `resource_hub.exe` 同级的那个文件夹），点击"选择文件夹"。
6. 如 Chrome 弹出权限提示，允许 **"读取和更改书签"**（`bookmarks` 权限在加载时授予）；
   若没有弹窗属正常现象，扩展加载完成即已授权。
7. 打开 Resource Hub → **工具设置 → 浏览器书签同步**，看到 **"扩展已连接"** 即成功。

> 提示：把扩展固定在工具栏（拼图图标 → 图钉）后，点击扩展图标可唤醒后台脚本，
> 在 App 重启后不必等它自动重连。

## 30 秒安装（Edge）

1. 先启动 **Resource Hub** 程序。
2. 地址栏输入 `edge://extensions` 并回车。
3. 打开左下角的 **开发人员模式**（Developer mode）。
4. 点击 **加载解压缩的扩展**（Load unpacked）。
5. 选择本文件夹 `bookmark-extension`，点击"选择文件夹"。
6. 如有权限提示，允许 **"读取和更改书签"**。
7. 打开 Resource Hub → **工具设置 → 浏览器书签同步**，确认显示 **"扩展已连接"**。

## 权限说明（为什么需要）

| 权限 | 用途 |
| --- | --- |
| `bookmarks` | 读取、删除书签，监听书签被删除/改名，用于双向同步 |
| `storage` | 记住桥接端口（47821-47830）和离线时待重发的事件，浏览器或后台脚本重启后不丢失 |
| `host_permissions: http://127.0.0.1/*` | 只访问本机回环地址上的桥接端口（47821-47830），与 Resource Hub 程序通信 |

扩展不会访问任何外部网站，不采集、不上传任何数据，也不包含任何远程代码或第三方依赖。

## 使用前提

- Resource Hub 程序**必须正在运行**：桥接服务只在程序运行期间开启。
- 扩展和程序在**同一台电脑**上（只走 `127.0.0.1`，不能跨机器）。
- 程序未启动时扩展会安静等待，只在后台控制台留一条提示，不会反复报错。

## 同步范围

- **删除**：在 Resource Hub 中删除书签 → 浏览器收藏夹内对应网址被删除。
- **改名**：在浏览器中重命名书签 → Resource Hub 内对应条目标题更新。
- **浏览器中删除书签** → Resource Hub 内对应书签被移除。
- 文件夹、`chrome://`、`edge://`、`javascript:` 等特殊地址会被忽略，不参与同步。
- 轮询间隔 1.5 秒：删除操作通常在 2 秒内生效；离线期间的浏览器端变更会缓存
  （最多 500 条），恢复连接后自动补发。

## 如何验证是否生效

1. App 内：**工具设置 → 浏览器书签同步**，状态显示 **"扩展已连接"**（以及端口号）。
2. 浏览器扩展管理页：找到"Resource Hub 书签桥" → 点击 **Service Worker / 检查视图**，
   控制台应出现一行：`[Resource Hub] 已连接本机程序 127.0.0.1:xxxxx`。
3. 快速测试：
   - 在 Resource Hub 里删除一个书签，刷新浏览器收藏夹，对应书签消失；
   - 在浏览器收藏夹里删除一个书签或给书签改名，回到 App 同步后对应条目被移除/标题更新。

## 故障排除

| 现象 | 处理办法 |
| --- | --- |
| App 显示"扩展未连接" | 确认 Resource Hub 程序正在运行；到扩展管理页点 **重新加载**；点一下扩展图标唤醒后台脚本；在 Service Worker 控制台看日志。 |
| 端口 47821-47830 被占用 | 扩展会自动扫描下一个可用端口，一般无需处理。若全部被占用，在命令提示符执行 `netstat -ano | findstr 4782` 找到占用进程并关闭，或重启 Resource Hub。 |
| 浏览器端删除/改名没有同步 | 等 2-3 秒（1.5 秒轮询 + 批量窗口）；确认该地址不在忽略列表（`chrome://`、`edge://`、`javascript:`）；查看 Service Worker 控制台是否有报错。 |
| 浏览器重装、升级或扩展文件夹被移动 | 扩展需要重新加载：扩展管理页删除旧条目 → **加载已解压的扩展程序** → 重新选择本文件夹。更新扩展文件后，在扩展管理页点 **重新加载** 即可。 |
| 换了浏览器配置文件 / 无痕窗口 | 每个浏览器用户配置文件需要各自加载一次扩展；无痕模式需在扩展详情里手动允许。 |
| 提示"清单文件缺失或不可读" | 选择的是扩展文件夹本身（需包含 `manifest.json`），而不是它的上级目录。 |

## 开发者自检（不需要浏览器）

```bash
# JS 语法检查（需要 Node.js）
node --check background.js

# 协议自检：启动模拟 bridge，校验 manifest/background.js 与 contract 一致
python check_protocol.py
```

`check_protocol.py` 只使用 Python 标准库：会静态检查端点、端口范围、1500ms 轮询间隔、
事件批处理/缓存参数，并在 `127.0.0.1:47821`（被占用则顺延到 47830，仍被占用则由系统分配）
启动一个与后端 contract 一致的模拟服务，逐项打印 `PASS` / `FAIL`，全部通过时退出码为 0。
